# Single Package, ein Docker-Image, zwei Entrypoints statt Monorepo

Das Repo ist ein einzelnes Node-Package mit einem Docker-Image; API- und Worker-Container starten aus demselben Image mit unterschiedlichem Entrypoint (CMD). Kein Monorepo (Turborepo/Workspaces): API und Worker teilen Job-Registry, Zod-Schemas, Storage-Seam und Credential-Code — das ist eine Codebasis, die lockstep deployt; ein Paket-Schnitt würde nur Versionierungs-Overhead erzeugen. Dass Postgres und Redis separate Coolify-Services sind (ADR-0005), erzwingt nichts an der Repo-Struktur: Die App sieht nur `REDIS_URL` und `DATABASE_URL` als Env-Vars, die Netzwerk-Anbindung (Predefined Network) ist reine Coolify-Konfiguration. Deployt wird als eine Docker-Compose-Resource mit `api`- und `worker`-Service — Compose ist wegen des Shared Volume (ADR-0004) ohnehin nötig, und ein späterer Worker-Split bleibt damit eine Compose-Änderung (ADR-0003).
